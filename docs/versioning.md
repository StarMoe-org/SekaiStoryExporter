# 版本策略

> ADR-0012：版本锁定 + 手动适配；长期项目，正确性优先。

## 三个版本号

| | 含义 | 位置 |
|---|---|---|
| 项目版本 | 本工具自身的版本 | `Cargo.toml` workspace version |
| **游戏版本** | 被支持的客户端版本（分区服） | `README.md` 支持矩阵；常量在 `sse_core::consts` |
| 资产版本 | Ripper 抓取的资产快照 | Ripper 输出里的 `ripper.lock.json` |

三者**不联动**。项目版本变化不代表支持的游戏版本变化，反之亦然。

## 支持矩阵

当前支持的（区服, 游戏版本）组合写在 `README.md`。两个区服共用一套代码：排版和常量相同，只有字体等素材随 UI 套件变化。
某个区服的行为出现差异时，常量按区服分组，由 Ripper 输出里记录的 `region` 选择，而不是复制代码。

## 游戏更新适配 checklist

游戏更新后按顺序执行。**不要跳步**：跳过的步骤会在三个月后以「某个分辨率下对话框偏了 2px」的形式回来。

- [ ] 1. 记录新的游戏版本号与资产版本号
- [ ] 2. 用新版本重跑 SekaiStoryRipper（`ripper rip`），比对 `ripper.lock.json` 的差异，列出新增或变更的资产；Ripper 输出格式升版时，同步升级 `ripper-format` 的 tag
- [ ] 3. 用 `tools/ui-kit/extract.py` 从新客户端重新导出 UI 套件，与旧套件逐文件比对
- [ ] 4. 重跑剧本语料统计（`tools/stats/`），检查是否出现新的 `SpecialEffectType` 或新的 Action 值
- [ ] 5. 复核 `sse_core::consts` 中的常量是否仍然成立
- [ ] 6. 检查 Cubism Core 版本 / moc3 版本是否变化
- [ ] 7. 复核色彩空间、CanvasScaler 设置、参考分辨率是否变化
- [ ] 8. 跑 L0 测试，并在本地做帧级回归
- [ ] 9. 更新 README 支持矩阵
- [ ] 10. 在 `CHANGELOG.md` 记录本次适配的发现

## 工具链版本

`rust-toolchain.toml` 钉死版本。升级工具链视为**可能改变浮点与优化行为的变更**：

- 必须走 ADR
- 必须在本地做跨平台帧哈希回归
- 不得与其他变更混在同一个 PR

## 破坏性变更

以下情况允许破坏兼容：

- IR / ParamTable 格式变更（两者都带版本号字段，旧文件应给出明确的「版本不匹配」错误而非乱解析）
- 坐标系或时间基约定变更（成本极高，需 ADR）

以下情况**不允许**静默变更：

- 任何会改变输出像素的修改，必须在 CHANGELOG 中标注
