# ADR-0015: 从 S3 读取 library、把输出写到 S3

- **状态**：accepted
- **日期**：2026-09-25
- **相关**：ADR-0006

## 背景

SekaiStoryRipper 可以把导出的 library 发布到 S3（它的 ADR-0012）。渲染节点往往不在导出那台机器上。sse 的各个 crate 都按本地文件读取资源：有的逐个文件读，有的按目录扫描（模型、特效 prefab）；影片还要交给 ffmpeg 按路径读取。

## 决策

- `--library` 可以写成 `s3://bucket/prefix`。sse 把它**镜像到本地缓存**（`--cache-dir` / `SSE_CACHE_DIR`，默认为平台缓存目录下的 `sse/`，布局 `s3/<bucket>/<prefix>`），其余代码照常读本地文件。
- **按 episode 同步**：加载一话时总是重新取它的索引。然后对索引 `bundles` 中的每个 bundle 取远端 `_ripper.json`：
  - `sound/…` 下的 bundle 只拉索引引用到的波形；
  - 其余 bundle 按 record 整包拉取，因为模型、动作、特效要按目录读；
  - 缓存里的 record 与远端不同时，删除整个 bundle 目录重新拉取；
  - record 最后写入，所以缓存里有 record 就说明这个 bundle 完整。
- **输出**：`-o s3://bucket/key` 先写到缓存目录下的 `outputs/`，完成后上传；`export` 的报告一并上传到同一目录。
- **签名**用 `rusty-s3`（SigV4 预签名），HTTP 用阻塞式 reqwest + rustls/ring，与 SekaiStoryRipper 一致，不引入 aws-lc 或 AWS SDK。
- **凭据只从环境变量读取**（`AWS_ACCESS_KEY_ID`、`AWS_SECRET_ACCESS_KEY`、`AWS_SESSION_TOKEN`）。端点、区域、寻址方式来自 `AWS_ENDPOINT_URL(_S3)`、`AWS_REGION`、`S3_ADDRESSING_STYLE`。
- 这不改变 ADR-0006 的边界：sse 仍然不接触游戏 CDN、清单和密钥，只是多了一个读取 Ripper 输出的途径。

## 后果

- 正面：渲染节点可以直接用对象存储上的 library，只下载一话实际需要的文件（SE 大包只拉用到的 cue）；渲染路径不变，输出与本地 library 逐字节一致。
- 负面：`sse-assets` 多了 HTTP 与签名依赖；缓存不会自动清理。

## 复审条件

需要流式读取、不落本地缓存时，或要支持对象存储以外的远端时。
