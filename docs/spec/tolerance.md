# 容差规范 v1

> 来源：ADR-0005。

## 两个独立容差

失败原因完全不同，**不可混用**：

- **T1 跨平台一致性** — 你的 macOS 渲染器 vs 你的 Windows 渲染器。
  差异来源只有 GPU / 驱动，**应当很严**：超过阈值基本就是实现分歧，不是浮点误差。
- **T2 对游戏保真度** — 渲染器 vs 同一剧情在游戏里的画面。
  差异来源还包括字体近似、shader 移植误差、布局参数抄错，**应当较松**。

## 阈值表

| 指标 | T1 跨平台 | T2 对游戏 | 说明 |
|---|---|---|---|
| 最大单通道差 | ≤ 1 | ≤ 4 | T1 超过 1 基本即为实现分歧 |
| 差异像素占比 | ≤ 2% | ≤ 5% | 分母为有效画面区域 |
| **差异的空间分布** | 必须全部落在几何边缘 ±1px 带内 | 同左 | **最重要的一条** |
| 大面积恒定偏移 | 不允许 | 不允许 | 出现即为色彩空间 / blend / 预乘 alpha 的 bug |
| 孤立高幅差异点 | 不允许 | 不允许 | 出现即为绘制顺序 / 遮罩 bug |
| SSIM | > 0.9995 | > 0.99 | **仅作趋势监控**，不作为独立判据 |

## 设计意图

主判据是**差异的形态**，不是差异的幅度。

放宽容差后最大的风险是「真 bug 被容差吃掉」：一个 `max diff = 1` 但均匀分布在整个对话框上的差异，几乎肯定是抄错了某个颜色值，却能轻松通过任何纯幅度阈值。

因此 diff harness 的输出**不是一个数字**，而是：

1. 差异热力图
2. **形态分类**：边缘带 / 区块 / 孤点 / 全局偏移
3. 分层归因（哪一层贡献了差异，需开启分层输出）

形态分类器比阈值重要得多，是 harness 的核心。

## 验收载体

逐位/容差验收在**未编码的 RGBA 帧**层面做，用 BLAKE3 帧哈希比对，**不在 mp4 层面做**。

后果：视频编码退化成无关紧要的最后一步。
- 两端可各自用喜欢的编码器（VideoToolbox / NVENC）做预览档
- 成片若需跨平台一致，用 `libx264` + 固定参数 + `--deterministic`
- 归档用无损（FFV1 / PNG 序列），harness 直接吃帧序列
