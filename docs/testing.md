# 测试策略

> 像素级目标要求把验证拆成可归因的层次：**每一层失败时，都应该能立刻说出问题在哪个模块。**

## 分层

| 层 | 验证对象 | 数据来源 | 需要游戏资产？ | 跑在哪 |
|---|---|---|---|---|
| **L0** 单元测试 | 曲线求值、时间轴编译、坐标转换、粒子发射、格式解析 | 手写 / 合成用例 | ❌ | CI（每次 push） |
| **L1** 参数级检查 | Pass 1 输出的参数表 | `sse bake` / `sse timeline` 的输出 | ✅ | 本地 |
| **L2** 帧级比对 | 最终像素 | T1：不同平台的渲染结果<br>T2：同一剧情在游戏里的画面 | ✅ | 本地 |
| **L3** 端到端冒烟 | 能否出片 | 一段短剧情 | ✅ | 本地 |

仓库里不能包含游戏资产（ADR-0006），所以 CI 只跑 L0；L1–L3 在本地用自己的 Ripper 输出和 UI 套件进行。
提交前请在本地执行：

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

动渲染路径的 PR，请附上改动前后同一批帧的比对结果（`sse render … --frame N`，逐字节相同或说明差异）。

## 为什么参数表是关键一层

Live2D 的失败模式很难定位：画面不对，可能是曲线求值错、淡入淡出权重错、Core 变形错，或者渲染错。
参数表把中间状态显式化以后：

- **参数表对上了** → 问题必在 Core 之后的渲染层；
- **参数表对不上** → 问题在动作、物理或状态机。

这把一个四维的 bug 空间切成两个二维的。

## 测试数据

- 不提交任何游戏资产或由其派生的二进制 fixture，也不使用 Git LFS（ADR-0014）。
- 需要真实资产的测试一律标记 `#[ignore]`，并通过环境变量指向本地数据，例如 `SSE_TEST_LIBRARY=<ripper-out>`。
- 结构化的期望值（哈希、计数、统计）可以入库。

## 测试命名约定

```
L0:  crates/<crate>/src/**（#[cfg(test)] mod tests）或 crates/<crate>/tests/
L1+: crates/<crate>/tests/*_local.rs（#[ignore]，需要本地资产）
```

## 不写什么测试

- 不为 wgpu、ffmpeg 等外部依赖写测试。
- 不为「代码能跑」写测试：L0 应该测**语义**（这个 anchor 配置在 19.5:9 下应该落在哪），而不是「函数不 panic」。
